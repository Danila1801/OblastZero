## 0. What Oblast Zero is, in one paragraph

A commercial roguelite shipping on Steam, built in Unity 6 + URP by a solo developer. Two phases per
run: **Phase A**, a 60-second first-person panic scavenge before a radiation emission hits; and
**Phase B**, a turn-based bunker management loop where you ration supplies and resolve data-driven
narrative events until you either reach one of four faction endings or your crew dies. The setting is
post-**administrative** rather than post-apocalyptic — Soviet-bureaucratic register, original IP, with
a hard firewall against S.T.A.L.K.E.R. names enforced by an automated content gate. Scavenge levels
are **generated by deterministic Python scripts**, not hand-authored in the Editor; the coordinate
plan is the reviewable artifact and the `.unity` YAML is output.

## 2. Bugs found and fixed

### 2.1 The compile gate was red, and the error blamed the wrong thing

`tools/verify_steam_layer.py` is the project's substitute for opening the Unity Editor: it does a
real `dotnet build` and asserts zero C# errors. It reported **26/29** with:

```
error CS0006: Metadata file '...vstuc-1.2.2\Analyzers\Microsoft.Unity.Analyzers.dll' could not be found
```

**Root cause.** Unity bakes an *absolute* path to the Visual Studio Tools for Unity analyzer into
every `.csproj` it generates, **with the version number in the path**. VS Code updated that extension
from 1.2.2 to 1.3.1, the old folder was deleted, and every `dotnet build` since has died on a missing
analyzer. The game code was fine. Nothing in the error text says so.

It could not be fixed in the csprojs: they are generated, `*.csproj` is gitignored, and Unity
overwrites edits on the next asset refresh. It could not be fixed in the scratch copy the gate builds
either, because the dead reference repeats in the package csprojs pulled in via `<ProjectReference>`.

**Fix.** A new `Directory.Build.targets` at the repo root drops any `<Analyzer>` whose file is not on
disk, for every project in the tree, immediately before compilation. Analyzers are advisory
diagnostics and cannot change the emitted assembly, so dropping a *missing* one is strictly better
than failing the build; analyzers that are present are untouched. Unity does not compile through
MSBuild, so Editor and player builds are unaffected.

**Negative control:** a deliberately introduced syntax error still takes the gate to 26/29 with three
real `CS` diagnostics. The fix removes the missing analyzer, not the diagnostics.

### 2.2 The item-weight gate was red, from a trap the docs describe but nobody closed

`tools/rebalance_weights.py --check` failed on all 8 hand-authored `.asset` items with nobody having
touched a weight.

**Root cause.** `OblastZeroContentSeeder.SeedItems()` (an Editor tool) recreates those 8 items from
**hardcoded pre-rebalance literals**. Running the seeder silently reverted the rebalance. The
project's own `CLAUDE.md` describes this exact failure mode under "Carry weight" — and the fix was
never applied. The gate blamed the assets; the cause was in the C#.

**Fix.** Applied the rebalance, corrected the 8 literals, and added a **mirror gate**:
`rebalance_weights.py --check` now parses the `MakeItem(...)` calls out of the seeder and asserts each
literal against `compute_weight()`. *Parsed, never mirrored* — a third copy of the numbers would drift
the same way. It also fails loudly if its own regex stops matching, because a mirror check that
inspects zero items passes forever.

**Negative control:** reverting one literal exits 1 and names the item.

### 2.3 The CI compile step could never have passed

`verify_steam_layer.py` hardcoded `PROJ = Path(r"C:\Users\danil\projects\OblastZero")` — correct on
exactly one machine. And even portable, the compile needs Unity's **gitignored** `Assembly-CSharp.csproj`
plus the engine DLLs from a local Editor install, neither of which exists on a bare GitHub runner.

**Fix.** `PROJ` now derives from `__file__`. A `--no-build` mode runs the 26 repo-only checks, and CI
uses it. This is not a weakening — it is the only honest thing the gate can do there. The compile is
covered by `unity-ci.yml`, which has a real Editor and a licence secret, plus the full 39-check run as
the local pre-push gate.

### 2.4 A latent gameplay bug the water requirement exposed

Both new levels need standing water that slows the player. `ScavengePlayerController.SpeedMultiplier`
was a single settable scalar whose doc comment declared the rule: *"one multiplier has one owner at a
time and resets to a known constant."*

That holds while anomalies are the only hazard touching speed. It stops holding the moment a second
**kind** of slow exists — and the two overlap *by design*, because the Reservoir's shortcut is a
Backlog anomaly inside a flooded tunnel.

**The failure:** wade into water (0.6×), cross a Backlog (0.02×), walk out — and `BacklogAnomaly`
restores an **absolute 1**. The player now sprints through waist-deep water at full speed for the rest
of the run. Permanently. Nothing logged.

**Fix.** `SpeedMultiplier` is now read-only and derived. `AnomalySpeedFactor` and `TerrainSpeedFactor`
are independent ratios composed by `ApplySpeedFactors()`, the single write site — the same shape the
codebase already uses in `AudioManager.ApplyBedPitches()` for music transpose vs. the Backlog's audio
drag. Wading through a Backlog is now correctly slower than either alone, and leaving one gives back
only its own share.

## 3. What was built

### 3.1 Shared level infrastructure (the enabling work)

Before this session, `generate_scavenge_scene.py` was 1,955 lines: a level plan **plus** ~490 lines of
rig (camera stack, player, HUDs, anomaly volumes, mutant spawner, dust, pickup emitter) **plus** ~600
lines of validation gates. Copying that twice would have produced three copies of the pickup emitter —
which is where silhouette selection, trigger sizing, tilt and scale spread all live, each tuned
against a real past bug. A fix to one copy would quietly not apply to the other two.

Extracted into:

- **`tools/scene_verify_lib.py`** — every gate, site-agnostic, taking each level's manifest as an argument.
- **`tools/scene_rig_lib.py`** — everything a Blowout level always has, driven by a `cfg` contract.

A site is now a **plan**: coordinates, a pickup manifest, anomaly volumes, fixtures, a dust box.

**Proof the refactor is behaviour-preserving:** `Scavenge.unity` and `navgrid_scavenge.bytes`
regenerate **byte-identical** (md5 unchanged) at every step. That check earned its keep immediately —
it caught a name substitution that had reached inside a string literal and renamed a scene group to
`=== cfg.PICKUPS ===`. Same object count, same line count, different bytes. Nothing else would have
seen it.

Two Grain Depot coordinates were also caught hiding in the supposedly site-agnostic module: the bunker
beacon and the entrance trigger. Both are now config fields. A hardcoded depot beacon would have put
the Census Office's exit light in a filing room.

### 3.2 Census Office — 286 GameObjects, 92 × 64 m

The Grain Depot is industrial and open; sixty seconds spent choosing a **route**. The Census Office is
the opposite building — narrow corridors, sealed rooms, and a lower floor that took the water when the
pumps stopped. Its sixty seconds are spent choosing **whether to go down**.

The flooded basement is deliberately a **dead end with one ramp**. Two ways down would make it a
shortcut and the wade would stop being a decision; with one, every metre of water is paid for twice.
That is why 5 of the 25 pickups — including a crew member and an artifact — are down there.

Anomalies as decisions: **Interview** in the sealed room off the *spawn* band, so it costs a detour in
the opposite direction from the exit. **Carbon Copy** over the centre stack row, on documents — light
items a player grabs without thinking about the carry cap, which is exactly the inattention the copies
punish. **Backlog** on the east doorway of the fastest line to the vault; going around costs ~8 seconds.

### 3.3 Reservoir — 199 GameObjects, 100 × 68 m

Asks both questions at once and charges for the answer. Three crossings between the banks, each bad
in a different way:

| Crossing | Character |
|---|---|
| Catwalk | Dry, fast, fully exposed over open water — and carries **no loot at all** |
| Service tunnel | The **shortest** crossing, shallow water, and the Backlog is inside it |
| Basin | Everything worth taking, under 1.4 m of water at half speed |

Nothing is on the catwalk. That is the design: the dry crossing has to cost something, and what it
costs is every pickup you did not stop for.

This site carries `CensusTakerCount = 2` and a 1.33× Editor chance — highest threat in the catalogue,
and the bible's hunting ground because this is where the Census-Takers drowned. **Three of the four
mutant spawn points are in water**: where the player is at half speed, the thing hunting them is not.

The tunnel Backlog is the strongest anomaly placement in the game — it is the price of the shortcut,
and it composes multiplicatively with the tunnel's own wade (0.6 × 0.02 = 0.012). That composition is
exactly why §2.4 had to be fixed first.

### 3.5 The best bug the gates caught

**The Reservoir's service tunnel built fine, verified fine, and could not be walked into.**

Its roof underside sat at 2.0 m, and the entry ramp meets ground level *inside* the tunnel footprint,
so the walkability flood-fill could not fit a 1.8 m character controller through the entrance. The
entire shortcut — three pickups, the Backlog anomaly, and a Census-Taker spawn point — was cut off
from the level, with **no error anywhere**. The scene was valid. The YAML was correct. A third of the
level's design was simply unreachable.

Confirmed by diagnosis (temporarily removing the roof made the tunnel reachable immediately), fixed by
raising the underside to 3.0 m.

The gates also caught, on first run: 14 Census Office pickups hanging in aisles or buried in a shelf
deck; 6 Reservoir bank pickups authored before the crates they sit on; and 2 pump-house pickups
centred on 4×4 housings, too far from any standable edge to reach.

## 5. What is NOT done, and why

Stated plainly so it is not mistaken for finished work.

### 5.1 Localization debt — 91 hardcoded strings, 5 screens

Five UI screens never call `LocalizedStrings` and render **English in every language, including
Russian**: `ArtifactUseUI` (30 literals), `InterviewSequenceUI` (30), `ExpeditionUI` (17),
`ScavengeHazardHUD` (14), `OblastUIAudio` (1).

Translating them is genuine authoring work — ~90 keys × three places each (a `UIStringKeys` constant,
an EN entry, an RU entry in Soviet-bureaucratic register). **Not attempted**, because half-translating
five screens is worse than clearly scoping them.

**What was done instead:** `localization_qa.py` gained `check_screen_coverage()`. This closes a
structural blind spot — the key-based checks reason about *keys* and are silent about a screen that
declares none, because from the tables' point of view such a screen does not exist. That is how five
screens shipped hardcoded with every localization gate green. `csharp_string_qa.py` does not close it
either: it is an IP/voice gate, and hardcoded English is perfectly in-voice, so it passes correctly
and says nothing about translation.

The debt is carried as an **allowlist with exact counts** rather than a red build — a gate that cannot
go green is a gate people learn to skip. A *new* unlocalized screen fails. An existing one that
*grows* fails. **The numbers may only move down.** Both negative controls fire.

### 5.2 No water audio

`WaterVolume` changes speed and the water is visible, but there is no splash or wade cue. No such cue
exists in `ProceduralSfx` (which synthesizes all 22 cues as PCM at boot — the project ships zero audio
files). Adding one means a new DSP primitive *and* its independent Python port in
`verify_procedural_sfx.py` (currently 32/32). **Deliberately not faked** by reusing an unrelated cue.

### 5.3 Play-mode verification — still the #1 blocker, and now bigger

**The game has never run end-to-end in Play mode.** This session did not change that, and could not:
it requires a human driving the Unity Editor.

It is now a **larger** job than the brief describes. Three levels need this pass, not one. Everything
above about Census Office and Reservoir is a claim about **geometry and reachability**, verified by
automated gates — not a claim about how they look or feel. Neither has ever been rendered.

**Prerequisites (human, in Unity):**
1. In the *MCP For Unity* window, switch Transport off `HTTP Local` — the bridge never opens its TCP
   port in that mode, so agent tooling finds zero Editor instances while the window shows a green
   "Session Active".
2. Create a `SteamConfig` asset (`Assets → Create → OblastZero/Steam/Config`), set the real App ID,
   assign it to `Bootstrap`, and add `SteamEventBridge` to the same GameObject.
3. Set `Application.runInBackground = true`.

**Specific things to check on the new levels:**
- Census Office: does the basement wade actually feel like a decision, or just a tax?
- Reservoir: is the catwalk's "no loot" cost legible, or does it read as an empty level?
- Reservoir: does the tunnel Backlog + wade combination land as brutal-but-fair, or as unsurvivable?
- Both: do the anomalies read before they are entered?

## 7. One recommendation

Editor open, walking all three levels end to end. Three complete scavenge levels, four endings, an
event engine with 1,020 events, 21 achievements and a Russian translation are all sitting behind a
